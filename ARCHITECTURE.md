# TAKTCO — Architecture Reference

For setup instructions, see `README.md`. This file is the technical map for developers picking up the codebase.

## Stack
Next.js 14 (App Router) + TypeScript + Tailwind, Prisma/PostgreSQL, custom email/password auth (not Auth.js — deliberate choice), Zustand (client UI state only), React Hook Form + Zod, Anthropic API (+ OpenAI/Gemini/xAI/Azure adapters for BYOAI), Stripe (3 distinct flows — see below), Resend, Twilio, Cloudflare R2/S3-compatible storage.

## Folder Structure
```
src/
  app/            Next.js routes only - pages, layouts, api/ route handlers. Kept thin.
  features/       Page-specific client components, grouped by domain (features/customers/, features/jobs/, etc.)
  components/     Reusable UI (ui/, layout/, forms/, marketing/) - no business logic
  lib/            Core business logic: auth, AI gateway, automation engine, job queue, error logging, crypto
  services/       External provider clients: stripe.ts, resend.ts, twilio.ts, openai.ts
  database/       Prisma client singleton (client.ts)
  emails/         Branded email HTML templates
  store/          Zustand stores (client-only ephemeral UI state - toasts, command palette)
  types/          Shared TypeScript types not generated by Prisma
  middleware.ts   Root middleware entrypoint (currently a deliberate passthrough - see file comment)
```

## Multi-Tenancy
Shared schema, row-level isolation via `companyId` on nearly every table, enforced at the application layer in every query (not database RLS). `requireSession()` in `lib/auth.ts` is the single choke point - every dashboard page/route calls it first and scopes all subsequent queries to `ctx.company.id`. This has held up across 8+ build phases without needing to change.

## Three Distinct Stripe Flows — Do Not Conflate
1. **Connect** (`stripeConnectAccountId` on Company) — a tenant's own customers pay *them* through a hosted Checkout Session created "on behalf of" the tenant's connected account. See `services/stripe.ts: createInvoiceCheckoutSession`.
2. **Platform billing (credits)** — TAKTCO charging a tenant for AI credit top-ups, on TAKTCO's own Stripe account. See `createInvoiceCheckoutSession`'s sibling in `/api/credits/checkout`.
3. **Platform billing (subscriptions)** — TAKTCO charging a tenant for their Starter/Pro/Corporate plan, also on TAKTCO's own account, but recurring. See `createSubscriptionCheckoutSession` + `createBillingPortalSession`.

All three share one webhook endpoint (`/api/webhooks/stripe`), disambiguated by event type and metadata, not by URL.

## Automation Engine (`lib/automationEngine.ts`)
Generic trigger → conditions → ordered actions, stored as data (`AutomationWorkflow`/`AutomationAction`), not code. `runTrigger(companyId, trigger, context)` is called from real app events (see grep for `runTrigger(` across `src/app/api` for every wired call site). A `DELAY` action persists an `AutomationScheduledAction` row and stops; `/api/automations/process-scheduled` resumes it later. Time-based triggers that can't fire from a single event (Task Overdue, Project Delayed, Invoice Overdue) are checked by `lib/checkScheduledTriggers.ts`, called from `/api/automations/check-triggers`.

**Both of those endpoints, plus `/api/jobs-queue/process`, need a real external cron trigger in production** (Railway's cron plugin or any scheduler) — nothing in the app calls them on a schedule itself. All three are protected by `CRON_SECRET`.

## Background Job Queue (`lib/jobQueue.ts`)
DB-backed (`JobQueueItem`), not Redis/BullMQ — deliberate, avoids new infrastructure this environment can't set up or test. Retries with simple linear backoff up to `maxAttempts`. Only `EMAIL_DELIVERY` and `SMS_DELIVERY` have a runner implemented; other job types are enqueue-able but still run synchronously at their current call sites (see `runJob`'s `default` case).

## AI Gateway (`lib/aiGateway.ts`)
Every AI-powered feature routes through `generateWithGateway()` rather than calling a provider directly. Nova AI mode: credit-metered against `AiCreditWallet`, uses TAKTCO's own Anthropic key. BYOAI mode: decrypts the company's stored key (`lib/crypto.ts`, AES-256-GCM) and routes to the matching adapter in `lib/aiProviders/index.ts`.

## Error Logging (`lib/errorLog.ts`)
`logError()` writes to `ErrorLog`, visible at `/admin/errors`. Wired into the highest-value failure points (email/SMS send failures, Stripe webhook signature failures) — not yet wired into every catch block in the app. `/admin/health` shows integration configuration status (env vars present, not live-verified) plus job queue and recent error counts.

## Database
45+ Prisma models. Full schema in `prisma/schema.prisma` — no separate ERD is maintained; the schema file with its inline comments is the source of truth. Run `npm run db:studio` for a visual browser.

## Deployment
See `README.md` §7 for the Railway walkthrough. Three cron-callable endpoints (above) need external scheduling configured separately from the app deploy itself.
